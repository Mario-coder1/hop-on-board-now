# Project rules
- Broadcast pushes carry the persisted notification ID and a same-origin profile deep link; load the targeted notification independently of the recent list so older messages remain readable under existing access policies.
- Use the shared rideDiscovery helpers for passenger listings and booking: a ride is joinable until departure plus estimated road travel time, afterwards only after the driver confirms it is still going (server RPC is_ride_joinable), consistently in lists, ride detail, payment function and the insert trigger.
- Keep payment administration focused on platform reservation fees and card authorization/capture/refund states, never driver payouts; drivers collect their fares separately and historical payout fields do not represent current payments.
- Preserve backend payment and refund behavior when updating public payment copy; wording changes must not alter money movement or historical records.
- Use the shared DriverSpokenLanguages display and spoken-language catalog on discovery cards so saved driver languages render consistently across screen sizes.
- Route shared ride links through the public `ride-share` Edge Function so social crawlers receive server-rendered route metadata while browsers continue to the protected ride page.
- Search metrics use consent-gated, debounced shared tracking with anonymous session UUIDs and result counts only; admin aggregates require server-verified roles and reservation totals remain separate from search conversions.
- Ride-detail location previews reuse useDriverTracking and label positions with their recorded time; unavailable or old GPS must never imply a current position or alter booking safeguards.
- Booking eligibility must stay consistent in the ride detail, payment function and database guards; active rides do not require LIVE activation, only the shared grace window after departure.
- Passed-pickup eligibility is authoritative in a database RPC/insert trigger using segment projection of persisted post-departure GPS; check before checkout and return the fee idempotently if the driver passes during payment.
- Return rides load an owned source ride by ID into the existing creation form, reverse endpoints and ordered stops, and recalculate road routing; only that source is exempt from the form's active-ride check, preserving other guards and payment behavior.
